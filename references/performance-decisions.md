# 性能候选、补证与采用决策

制定或调整性能优化计划，以及执行候选保留、待确认项推进、退化修正和采用取舍时，读取本文件。规划阶段据此安排补证路径、独立交付切片、轻微退化的修正条件及最终验收和交付预算；仅有规划授权时不执行实施操作。先核实当前批准范围、测量协议、总预算及剩余安排；本文件不增加实施、改协议或批准例外的权限。普通功能验证无需读取本页。

## 固定比较与保护范围

固定项目起点 B0 和上一已按项目批准采用条件验收的检查点 B*；B* 可以含明确批准的单项例外，原严格成绩及批准范围仍单列。记录核心路径、重要保护和边缘场景的公开调用、输入规模、使用条件与价值。保护范围依据共享代码、分发、资源行为和编译影响确定，不只看改动行数；调用频次无证据时记为未知。

沿用已批准的逐项耗时指标、保护线及收益目标，不因本引用另设门槛。新项目在测量前明确轻微真实超限需要追加产品修正的判断依据；旧项目只有保护线、尚无临界范围时，根据超限幅度、绝对代价和实际影响提出具体判断，并在采用取舍前按授权确定。不能以未另设范围为由跳过修正，也不从来源案例复制固定百分比。

## 主动查证，并行推进不受影响部分

1. 待确认项逐项写明待判问题、现有证据、下一可行办法、预期结果、预计用时和检查点。在授权和预算内主动查证，直到足以作出判断；一个办法无效时换能取得新证据的办法，不只登记后搁置，也不无信息增益地重复。
2. 某项已具备正式补证条件就推进，不等同组其他项全部就绪。固定问题项清单与确定依据，保留全部结果和未决状态；逐项调度不删减保护，不按胜负选项。既有协议明确要求整组准入时，提出保留全清单和门槛、仅调整调度的具体方案，按原授权处理。
3. 单一路径次数用尽不等于所有办法用尽。仍有可行新办法和预算时，给出有界下一方案；在既有授权内调整执行，涉及冻结协议或硬限额变更时取得必要决定后再做。保留已用次数和原时间账，不靠新配置或新会话刷新限额。
4. 待确认项不自动阻塞项目。先核实它是否为当前交付的实际必需依赖，并检查补证、修正、独立切片或回到 B* 能否解除影响。只有必需依赖无法在可行办法、授权和预算内解决时，才阻塞受影响部分，并列明缺口和恢复条件；其他已授权工作与可独立验收成果继续。必要保护未满足的候选不能因“项目继续”而直接采用。

保留候选源码、构建身份、已验证收益和失败证据。证据不足不是无收益；有充分证据证明没有采用价值时才按停止条件放弃。暂停或未采用不删除候选及其恢复依据。每轮沿用项目台账简短记录假设、改动、证据、实际用时和下一动作，不重新编制整份计划。

## 先修正真实退化，再作取舍

1. **核实真实性。** 同义调用、产物身份、完整覆盖、测量质量和必要精度成立后，才将可靠超限归为真实退化；否则先补证。保留初始数据，不把已证明的退化归咎于噪声。
2. **减少额外工作。** 优先查重复准备、复制、分配、同步和调度成本。每轮针对一个原因作有界产品修正，并复验原主要收益、变慢项及相邻路径。只有两侧数据支持且分流自身成本可接受时才引入规模阈值。
3. **临界超限再做实际修正。** 可靠耗时超过项目保护线、属于已确定的轻微超标追加修正范围时，再做一轮实际产品优化。按原预设中位或保守指标判断，覆盖项目明确包括的同类临界项，不能靠百分数取整避开。同一原因影响多项可合并修正、逐项复验；本轮已针对该原因完成的修正可计入，不因换报告或逐项列账重复要求一轮。计时预试、改采样和只重测不算产品修正。确无安全改法或授权时间不足时，写明已查原因、不能安全修正的依据、追加修正未完成和恢复点，不自动取得例外。
4. **比较修正后的同一候选。** 对照 B0 和 B* 展示相关场景的绝对耗时及相对变化；按实际影响检查峰值内存、首次与重复调用的 CPU 代价、尾部耗时和维护复杂度，不强制测量无关指标。保护线内的退化也按实际用途评估。有可靠频次时，用同一业务窗口内的绝对耗时差乘调用次数估算累计影响；频次未知则并列展示，不编造权重或用总体平均抵消未获批准的单项回归。
5. **明确采用决定。** 核心收益显著、边缘代价实质较小且证据支持时，按项目授权审议具体速度例外；时间在保护范围内且资源显著改善时，可按资源收益采用。仅稳定性超限时按项目适用测量协议审议稳定性例外，不把真实速度退化包装成稳定性问题。没有适用的例外条件或批准权限时，提出所缺决定，不自行批准。性能例外不替代功能、正确性、安全、结果精度、所有权、缺失值、异常和真实回调保护。

逐项记录采用、回退、继续验证或获批例外，保留初始失败、修正前后结果以及放弃方案的收益和代价。临界清单包括已修好、已采用、已舍弃和仍待定项。严格成绩不因采用而改写；可一次批准明确列出的多项，但每项仍有独立证据和适用条件。

## 把收益保存成可回退检查点

每个实验先解决一个可解释的成本环节，保存可重建、可独立验证及撤回的改动。整体候选受阻时，将可独立成立的高收益部分放到 B* 上重建并复验；通过本切片的必要采用条件后晋级为新 B*，同时保留 B0 和上一可恢复版本。

已满足切片采用条件的改进，即使尚未达到项目最终性能目标，也作为后续基础保留；未达到的必要目标继续列为项目缺口，不能因切片已交付而宣布整个项目完成。

多个切片合并后验证共用路径及相互影响，不能拼接各旧候选的成绩。保留当前采用对象和下一待验证候选的身份；最终构建、安装和实际使用证据按 [验证与最终版本证据](validation-and-evidence.md#有效证据与最终交付版本) 核对。
