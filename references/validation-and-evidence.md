# 验证、优化与最终版本证据

新增调查或测试、评估优化候选、复用证据、开展性能比较及汇总最终验收时，读取本文件。仅规划时把这些要求落入步骤和预算；沿用实施授权后才执行对应操作。

## 让验证和优化直接服务目标

每项新增测试、调查、扩展或优化都应能说明：保护哪个要求、已有证据为什么不足、失败影响哪个步骤，以及什么结果出现后停止。可以引用所属步骤，不另写重复文档；无法对应本次目标的事项不加入。

必要覆盖由行为差异和真实风险决定，不用任意用例数量上限裁掉边界。失败时先缩小为可复现输入，再修复并验证相关范围。

### 快速开发与优化路径

默认顺序：正确性检查 → 少量目标场景比较 → 保留或放弃候选 → 验证受影响的保护场景 → 最终候选完成约定全量验收 → 完成约定独立复核与交付验证。

经可靠测量证明确有收益，且通过功能、兼容性、安全检查及所有预设保护门槛的优化，即使未达到最终性能目标，也应保留为后续优化的基础，并在既定总预算内继续推进。成果保留与最终验收须分开判断；预算结束时仍未达标，应交付已验证的改进及证据，明确标记为“未通过性能验收”，不得降低门槛或将部分成果报告为项目完成。

每次候选只简短记录假设、验证范围、停止条件、决定和证据，不重新编制整份项目计划。

- 质量合格且足以判断的证据表明没有改善方向时，按预定停止条件及时放弃候选；噪声较大或证据不足时仍属待判定，不据此认定没有改善。
- 出现可靠回归时，先与预定保护门槛及允许退步范围核对。违反必须保护要求或超出允许退步范围，才因该回归停止采用相关改动；允许范围内的差距应如实保留，不自动判失败。
- 噪声较大或证据不足时，结论为待判定，不能判成功或失败。按预先约定的次数、用时和停止规则有限补测；仍不明确就报告不确定性与验收影响，不无限重跑。
- 保护范围依据共享代码、分发、资源行为和编译影响确定，不能只依据改动行数。
- 定向比较用于开发决定，不能冒称完整验收；最终验收覆盖全部约定要求，不省略仍受影响的保护项。

### 性能比较要求

使用轻量、快速、可复用的测量工具，不建设无必要的界面、服务或通用测试平台。

- 计时前确认行为正确，不能靠错误结果、跳过工作或改变语义取得速度优势。
- 固定输入、工作负载、比较对象、计时边界和统计方法。
- 比较各方采用公平的准备与运行条件，完成协议要求的配对。
- 区分数据是否完整、质量是否合格、统计是否稳定和性能是否达标。
- 保留场景级退步，不能用总体平均掩盖不允许的回归。
- 保留原始样本、摘要和必要环境记录，按预定规则处理无效数据，不挑有利结果。
- 没有业务频率依据时，不声称覆盖实际使用量的某个百分比。

具体采样、环境判定、统计和复测规则引用直接适用的性能测试 skill 或项目协议，不在本模板重复维护一套细节。

### 有效证据与最终交付版本

已有证据覆盖本次要求，且相关身份和条件仍有效时直接复用。正式统计采样、故障复现、稳定性测试、约定独立复核，以及变更引起的针对性复测，均须有明确用途、有限停止规则和时间安排。

性能及原生构建证据按需要绑定源码、实际加载产物、运行器、输入、环境和测量配置。功能、性能和安装证据分别判断有效性。

最终验收结论必须对应同一个明确的最终交付版本。不能把不同候选各自通过的部分拼成“全部通过”，也不能把旧产物的性能样本改署为新产物的成绩。

这不要求无差别重跑全部验证：没有受到最终变更影响、身份及适用条件仍成立的证据可以复用；记录其来源、覆盖范围和复用依据。受影响的部分针对性补齐，汇总时明确其对最终版本的适用性。

历史基线可复用，不代表可以把不匹配的单方结果拼成新的配对成绩。局部替换须遵守事先约定的复用条件，保留原记录和每项实际配置。

纯注释或文档变更按实际影响决定必要核验，不能仅因源码哈希变化就无差别重跑全部性能，也不能因此跳过确实受影响的构建、文档或静态检查。
